# ROADMAP

## После хакатона: приоритет 1

1. **Очередь фоновых задач (Celery/RQ + Redis или отдельный worker).** Сейчас конвейер выполняется в процессе backend. Нужны повторяемые задачи, восстановление после перезапуска и горизонтальное масштабирование.
2. **Production-аутентификация:** httpOnly refresh-cookie с ротацией, access-token в памяти, 2FA для сотрудников и администраторов, SSO организации.
3. **Несколько пользователей на компанию:** владелец, бухгалтер, финансовый директор; приглашения и матрица прав внутри компании.
4. **Лимиты повторных подач:** cooldown после отказа, максимальное число заявок в периоде, антифрод-проверки и защита от автоматизированного перебора ИНН.
5. **Выгрузка аудита во внешнее неизменяемое хранилище:** WORM/S3 Object Lock, периодическая якорная публикация корневого хеша, независимая проверка.
6. **Полный production-мониторинг:** OpenTelemetry-трейсы, метрики конвейера и SLA, алерты по деградации моков/источников, дашборды нагрузки.

## Продуктовые возможности

- **OCR документов:** извлечение реквизитов и финансовых показателей из PDF/сканов с обязательным подтверждением человеком; хранение исходников и версий распознавания.
- **ИИ-ассистент в кабинете:** открытая модель (например, Qwen2.5-1.5B-Instruct, Apache-2.0) отдельным контейнером Ollama в том же `docker compose`, работает на CPU. Модель только понимает запрос клиента и формулирует ответ; продукт подбирает существующая кредитная логика. Без модели — резерв на правилах по ключевым словам. В контекст попадают только данные текущего клиента.
- **Подсказки сотруднику:** объяснение факторов скоринга, аналогичные рассмотренные кейсы, чек-лист проверок; решения остаются за человеком.
- **Расширение кредитной логики:** несколько продуктов в одной заявке, кредитный комитет, ручное изменение ставки с обоснованием, ограничения по концентрации.
- **Работа с офертой:** полноценный PDF-документ, версии условий, электронная подпись через внешнего провайдера (при появлении легального контура), архив документов.
- **Уведомления в продукте:** настройки категорий, группировка, срок жизни; по-прежнему только внутренний центр.
- **Аналитика:** воронка заявок, доля исходов, SLA по сотрудникам, причины отказов, влияние факторов скоринга на решения.

## Инженерный долг

- Перевести rate limit в Redis и учитывать распределённые IP.
- Добавить contract-тесты OpenAPI и проверку breaking changes.
- Добавить миграционные тесты на PostgreSQL в CI (в текущем прототипе unit-тесты используют SQLite, а триггер аудита проверяется в контейнерной среде).
- Добавить резервное копирование PostgreSQL и тома документов, политику хранения и удаления.
- Ограничить размеры очередей и ввести backpressure при массовой подаче.
- Усилить CSP с nonce для Swagger UI и вынести статические ассеты через CDN только при наличии доверенного контура.
- Локализовать ошибки Pydantic на уровне полей для всех сценариев.
- Улучшить доступность: аудит контраста и клавиатурной навигации, aria-атрибуты для динамических статусов.

## Что осознанно не делаем

- Мобильное приложение: кейс требует веб-интерфейс.
- Внешние каналы подтверждения и рекламные коммуникации: запрещены условиями.
- Реальные кредитные решения, переводы и ПДн: прототип использует только синтетические данные.
- Платные API, корпоративные лицензии и закрытые модели: ограничение хакатона.

## Идея на будущее

- Персонализированная новостная лента клиента (по продукту, отрасли и этапу заявки): намеренно убрана из прототипа, потому что не нужна для сквозного кредитного сценария. Вернуть можно отдельным модулем: модель новостей, правила показа по профилю клиента и блок на дашборде.
